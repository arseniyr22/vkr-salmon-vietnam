## Часть 1. Архитектура работы с ИИ (слайды 3-5)

### Без пайплайна vs с пайплайном

| Без пайплайна | С пайплайном |
|---|---|
| Одноразовый промпт — результат не воспроизводим | Структура: источники → анализ → верификация → результат |
| Нельзя объяснить комиссии, откуда данные | Каждый шаг документирован и проверяем |
| Каждый раз начинаешь с нуля | Прозрачно для НР и комиссии |
| Нет контроля версий источников | Можно повторить, улучшить, защитить |

### Архитектура пайплайна (слайд 4)

`Источники → Обработка (NotebookLM/LLM Project) → Анализ (промпт + контекст) → Верификация (вручную) → В ВКР`

Структура папок проекта (рекомендация Кнатько):
```
01_sources/   (PDF, данные, транскрипты)
02_embeddings/  (NotebookLM)
03_prompts/   (ваши промпты как .md)
04_outputs/   (raw + verified)
05_drafts/
```

### Три типичных пайплайна (слайд 5)

- **А — Теоретический обзор (Глава 1):** 15+ PDF → NotebookLM → промпт на research gap → верификация ссылок → матрица концепций → текст
- **Б — Анализ данных компании (Глава 2/3):** Данные → Excel/CSV (**ЛОКАЛЬНО, не в облако!**) → Python-код через ИИ → запуск локально → проверка → графики в ВКР
- **В — Черновик раздела:** Черновой набросок → Черновик → Структурирование → Критическая переработка → Итоговый текст

**Ключевое правило (слайд 5):** «Текст и данные ваши — ИИ помогает. Всё проверяется вручную.»

## Часть 2. Декларация ИИ — формат и требования

### Три требования к декларации (слайд 6)

Декларация — обязательный раздел при загрузке ВКР в LMS.

**НЕТ:** «Я использовал ChatGPT для помощи в написании работы».

**ТРЕБУЕТСЯ:**
1. **Часть работы** — конкретный раздел, не «вся работа целиком»
2. **Цель** — поиск / структурирование / редактура / анализ / код
3. **Инструмент** — название, модель, версия (пример Кнатько: «Claude 3.7 Sonnet, claude.ai»)

### Структура одной строки декларации (слайд 7)

```
Раздел ВКР — Цель ИИ — Инструмент — Входные данные — Действия студента — Результат и оценка
```

### Пример таблицы декларации (слайды 8-10) — формат исследовательской и проектной ВКР

Для **исследовательской** ВКР (слайд 8) — пример из 3 строк:

| Раздел ВКР | Цель ИИ | Инструмент | Что сделал студент после |
|---|---|---|---|
| Глава 1: Теоретический обзор | Систематизация источников, research gap | NotebookLM (18 PDF) | Верифицировал ссылки, переформулировал текст |
| Глава 2: Анализ данных | Написание Python-кода для обработки HR-данных | Claude 3.7 (данные локально, не загружались) | Запустил локально, проверил логику, интерпретировал сам |
| Все главы | Улучшение стиля и грамматики | ChatGPT-4o | Критически переработал каждый фрагмент |

Для **проектной** ВКР (слайды 9-10) — расширенная таблица с 6 колонками: №, Раздел ВКР, Цель ИИ, Инструмент, Входные данные, Что сделал студент, Оценка. Пример: 5 строк (диагностика, анализ финансов компании, анализ интервью N=12, проверка стилистики, выявление отклонений от ГОСТ).

В конце таблицы (слайд 10) — **итоговая оценка применения ИИ**:
> «ИИ использовался для ускорения рутинных операций: сбор данных, диагностика, генерация кода, вычитка. Все содержательные решения — выбор методов, интерпретация данных, разработка программы, расчёт эффекта — результат самостоятельной работы автора. Каждый вывод верифицирован вручную.»

И ссылки на исходники:
> Исходные материалы доступны по ссылке: ___
> Промпты доступны по ссылке: ___
> Исходные тексты доступны по ссылке: ___

### Семь критериев хорошей декларации (слайд 11)

1. **Пайплайн виден** — понятно: что до ИИ, что после ИИ
2. **Конкретика инструмента** — не просто «ChatGPT», а модель + версия + способ доступа
3. **Разграничение вклада** — чётко: что сделал ИИ, что сделал студент
4. **Честность про ошибки** — указаны галлюцинации, отклонённые правки, баги
5. **Данные защищены** — данные компании НЕ загружались, код — локально
6. **Повторяемость** — другой человек может воспроизвести каждый шаг
7. **Оценка эффективности** — не «использовал», а «сократило время на X%»

### Чего стоит избегать (слайд 11)

- «Использовал ChatGPT для написания работы» → нет конкретики, нет пайплайна
- Скрывать факт использования ИИ → обнаружится на защите
- Загружать конфиденциальные данные компании в облачные ИИ
- Писать декларацию в последний день → детали уже не вспомнить

## Часть 3. Защита (слайды 12-22) — пригодится позже

Сохраняю кратко, разберём отдельно при подготовке к защите.

### Ключевой принцип защиты (слайд 12)
Защита — не экзамен на знание текста, а **«продажа» бизнес-решения перед советом директоров** (для проектной ВКР). Задача — подтвердить ценность вклада перед стейкхолдерами.

### Модель «3 ворот» (слайды 13-14) — критерии комиссии
- **Ворота 1 — Обоснованность и актуальность:** проблема реальная и доказана? Тема конкретна? Формат соответствует цели?
- **Ворота 2 — Методологическая обоснованность:** методы адекватны задачам? Логика последовательна? Решение обосновано?
- **Ворота 3 — Результативность и ценность:** есть конкретный результат? Отвечает на проблему? Практическая ценность?

Для проектного трека — частые вопросы: «Почему именно этот фреймворк?», «Реалистично ли внедрить?»

### Частые ошибки, влияющие на оценку (слайд 15)
1. Нет доказанной проблемы — «кажется, это важно» без цифр
2. Методы без обоснования
3. Результаты без оценки эффекта и ключевых инсайтов
4. Не определены ограничения
5. Не выступление, а чтение с экрана
6. Финансовый эффект «с потолка» — цифры без методологии

### Структура презентации (слайд 17) — 10-15 слайдов, 15 минут
1 — Титульный (10 сек)
2 — Проблема + актуальность (2 мин)
3 — Цель и задачи (30 сек)
4-5 — Методология и исследование (2 мин)
6-10 — **Ключевое решение, план внедрения, эффект (5-7 мин)** — главная часть
11-12 — Выводы + рекомендации (1 мин)
13 — Ограничения (30 сек)
14 — Заключение (30 сек)

### Образ комиссии (слайд 16)
Состав: 5-7 человек. Председатель — обычно топ-консультант или C-Suite. 50%+ — практики из бизнеса. Остальные — преподаватели ВШБ.

Вопросы они задают себе: «Возьму ли я этого человека в команду?», «Доверю ли проект на $500K?», «Понимает ли он, или вызубрил?»

**Вдохновляет:** глубина, конкретные цифры, честные ограничения, уверенность, связь с практикой.
**Вызывает вопросы:** чтение с листа, путаница в терминах, «идеальное» решение без ограничений, агрессивный спор.

### Алгоритм ответа на вопросы (слайд 21)
1. Пауза — собраться, при непонимании переспросить
2. Прямой ответ — Да/Нет/Частично/По-другому. Не оценивать вопрос («хороший вопрос!»)
3. Аргументация — данные, источник, логика. 1-2 предложения, не монолог
4. Связь с работой — как это связано с целью/результатами ВКР
5. Завершение — «Ответил ли я?» или просто остановиться

### Если не знаете ответ (слайд 22)
- Плохо: придумывать на ходу или сказать «не знаю» и замолкнуть
- Вариант 1 — Честное признание + план: «Я не изучал этот аспект, фокусировался на X. Если бы продолжал, я бы…»
- Вариант 2 — Переформулирование: «Если правильно понимаю, вы спрашиваете о Y. В работе я рассматривал похожий аспект…»
- Вариант 3 — Ссылка на ограничения: «Это ограничение моего исследования, отмечено в разделе…»

### Mock-защиты (слайд 23)

## Что отсюда забираем как обязательные правила для нашего проекта

1. **Журнал использования ИИ ведётся параллельно с написанием**, не в последний день — `AI_USAGE_LOG.md`.
2. **Структура каждого эпизода** — 6 колонок по слайду 7.
3. **Промпты сохраняются** — для требования «повторяемость» (п. 6 чек-листа).
4. **Финальная декларация** — 10-12 страниц (целевой), max 15. Внутренний лимит, согласован с Арсением.
5. **Дисклеймер строится по 7 критериям слайда 11** — это чек-лист готовности раздела.
6. **Salmon — публичная информация, внутренних данных нет** → пункт «Данные защищены» выполнен автоматически, явно зафиксировать.
7. **Структура папок ai_pipeline/** соответствует рекомендации Кнатько (`prompts/`, `raw_outputs/`, `verified/`).
8. **Ключевое правило** — текст и решения мои, ИИ помогает; всё проверяется вручную → шаг 6 цикла подглавы (защитимость устно) — основной фильтр.
