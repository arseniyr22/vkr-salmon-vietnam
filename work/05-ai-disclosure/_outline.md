## Что это и что это НЕ

**Это:** раздел финальной ВКР с описанием методологии использования ИИ. Загружается в LMS вместе с основным текстом работы. Формальное требование академической этики ВШЭ; отсутствие в первой версии было одним из формальных оснований отказа Кнатько.

**Это НЕ:**
- **Не** GitHub-репозиторий с `ai_pipeline/` и `AI_USAGE_LOG.md` — это раздел внутри финального `.docx`. GitHub-репозиторий с raw-материалами — это **отдельный артефакт** (аудит-trail), и оба обязательны по семинару 14-15.
- **Не** одна страница «использовал Claude для помощи» — Кнатько прямо отметил такой формат как недостаточный.
- **Не** пересказ инструкций («как пользоваться ИИ») — это рассказ о том, **как именно** ИИ применялся в данной работе.

## Структура — 7 критериев слайда 11 семинара 14-15

Каждый критерий должен быть закрыт явно, с конкретным примером из проекта. 3 смысловые части ниже распределяют 7 критериев между собой.

1. **Пайплайн виден** — описано: что было до ИИ → что делает ИИ → что делает автор после
2. **Конкретика инструмента** — модель + версия + поверхность доступа: (a) Claude Opus 4.7 в Claude Code в VSCode для содержательного анализа; (b) Claude Sonnet 4.6 в Claude Code для рутинных операций харнесса (маршрутизация автоматическая); (c) Perplexity Sonar Pro через OpenRouter API для поиска источников
3. **Разграничение вклада** — для каждой задачи явно: что произвёл ИИ, что произвёл Арсений
4. **Честность про ошибки** — какие галлюцинации найдены, какие правки отклонены, какие выводы пришлось переделать
5. **Данные защищены** — Salmon: только публичная информация, внутренних данных нет
6. **Повторяемость** — все промпты в `ai_pipeline/prompts/`, raw outputs в `ai_pipeline/raw_outputs/`, `AI_USAGE_LOG.md` с per-episode деталями
7. **Оценка эффективности** — не «использовал», а «сократило время на X», «помогло с Y», «не помогло с Z»

## Смысловая часть 1. Архитектура работы с ИИ и стек инструментов (~1500-2000 слов / ~5-7 страниц)

Закрывает критерии: **1, 2, 6.**

- Архитектура пайплайна: Источники → Анализ → Верификация → ВКР (пересказ слайда 4 семинара применительно к проекту)
- Структура папок (`ai_pipeline/prompts/`, `raw_outputs/`, `verified/`)
- Стек инструментов: Claude Opus 4.7 (содержательный анализ), Claude Sonnet 4.6 (рутинные операции харнесса) — оба в Claude Code в VSCode; Perplexity Sonar Pro через OpenRouter API для поиска академических источников и свежих regulatory данных
- Workflow: Claude Opus делает обучение, драфты, проверку и Council Review; Perplexity ищет реальные источники для Шага 2 (план) и верифицирует данные в Pass 1 (фактология) и P3 (date-anchor)
- Цикл подглавы: 7 шагов с обучающим, 4 прохода проверки (фактология / аргумент / стиль / Council Review), защитимость устно
- Откуда взялась эта система — feedback Кнатько мая 2026, манифест PRINCIPLES.md, DEFENDABILITY.md по работе одногруппника

## Смысловая часть 2. Разграничение вклада и журнал эпизодов (~1500-2500 слов / ~5-8 страниц)

Закрывает критерии: **3, 4.**

- Что делал ИИ: формулировки, обучающие объяснения концептов, первые драфты подглав, AI-проходы проверки, Council Review
- Что делал Арсений: понимание темы (Шаг 1 цикла), выбор углов и аргументов, верификация фактов и источников, окончательный текст, защита устно
- Сводка по `AI_USAGE_LOG.md`: сколько эпизодов, по каким категориям (поиск / структурирование / драфт / проверка / перевод)
- 2-3 показательных эпизода с конкретикой
- Журнал ошибок ИИ (галлюцинации, отклонённые правки) — конкретные примеры из `AI_USAGE_LOG.md` Раздел 5

## Смысловая часть 3. Защита данных и оценка эффективности (~600-1200 слов / ~2-4 страницы)

Закрывает критерии: **5, 7.**

- Salmon: работа только с публичной информацией (отчёты IFC, открытые данные SBV/Statista/World Bank, публикации Salmon в прессе). Внутренние данные компании в проект не загружались — риск утечки автоматически закрыт
- Запросы к Perplexity Sonar Pro: только публичные search-запросы (название теории, regulatory ключевые слова, открытая информация о компании); ничего конфиденциального в API не передаётся
- OpenRouter API key хранится только в локальном `.env`, в `.gitignore`; при публикации проекта на GitHub ротируется
- Цитата ключевого правила слайда 5 семинара: «Текст и решения мои, ИИ помогает, всё проверяется вручную»
- Оценка эффективности: что сократило время, что не сократило, что пришлось переделать
- Ссылки на исходники: `AI_USAGE_LOG.md`, `ai_pipeline/`, GitHub-репозиторий

## Когда писать

**Финальный сборочный этап**, после того как готов основной текст ВКР. Источник материала — `AI_USAGE_LOG.md` (растёт по мере работы), `ai_pipeline/` (промпты и raw outputs), `MEMORY.md` (Session log).

Не писать заранее — пока неизвестно, какие именно эпизоды войдут, какие ошибки ИИ обнаружатся, как именно работала система.
