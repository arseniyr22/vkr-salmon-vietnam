# PROJECT_CONTEXT — рабочий контекст проекта

> Заполняется по мере поступления материалов от Арсения.
> Этот файл — не план работы и не memory. Это «папка-сборник» проектного контекста, на который Claude опирается при работе над подглавами.
> Первая версия — 2026-05-09.

---

## 1. Сроки и процесс

- **Дедлайн:** сдача текста диплома. Точная дата не критична для темпа.
- **Промежуточные дедлайны:** нет других академических обязательств — всё внимание на ВКР.
- **Корректирующий контакт с Кнатько после его feedback:** не будет. Дополнительная встреча до защиты маловероятна.

**Что это значит для работы:** нет промежуточной проверки руководителем перед защитой. Каждая подглава должна быть готова сразу под защиту, не «под показ научруку с правками». Защитимость устно (шаг 6 цикла) — не финальный лак, а основной фильтр.

---

## 2. Объект — Salmon

- **Что Арсений знает на старте:** общая информация — чем компания занимается, где находится. Глубокого погружения нет.
- **Доступ к компании:** материалы, собранные Арсением (общего характера), будут переданы Claude по частям.
- **Статус входа во Вьетнам:** **гипотетический.** Salmon ещё не зашла на этот рынок. Подробнее — Арсений добавит контекст позже.

**Что это значит для работы:** ВКР строится как **проектная рекомендация перед входом**, не post-mortem уже состоявшегося входа. Это влияет на формат Chapter 3 (evaluation): оцениваем перспективную стратегию, не фактические результаты.

---

## 3. Стартовая база Арсения

- **Что есть:** материалы, которые он сам собирал во время предыдущей итерации работы.
- **Где находится полезное:** часть — в скинутых материалах (поступят по частям), часть — внутри отклонённой версии в `reference/_archive/`.
- **Риск:** старая версия — токсичный контекст (Кнатько распознал её стиль и структуру). Любое заимствование из неё тащит провальный паттерн.

**Что это значит для работы:** старую версию Claude **не открывает** без явного указания Арсения. Когда Арсений скажет «посмотри в архиве 1.2 как было сформулировано Х» — открываем тот один раздел, **извлекаем факты/источники, не формулировки**, закрываем и пишем с нуля своими словами.

---

## 4. Язык

- **Драфтинг:** русский. Так Арсений лучше понимает, что написано, и может проверить защитимость.
- **Финал:** перевод на English после того, как полный текст согласован.

**Что это значит для работы:** все драфты подглав — по-русски. Перевод — отдельный этап в самом конце, не параллельно. Терминологию (entry modes, OLI, Uppsala, RBV, TCT, sandbox) удерживаем в обоих языках сразу — англоязычные термины оставляем латиницей даже в русском тексте, чтобы потом не пере-переводить.

## 5. Декларация использования ИИ

Зафиксировано 2026-05-09 на основе НИС Кнатько 14-15 (декабрь 2025) — см. [reference/knatko_seminars/seminar_14-15_2025-12_AI_disclosure_and_defence.md](reference/knatko_seminars/seminar_14-15_2025-12_AI_disclosure_and_defence.md).

### Объём
Целевой — **10-12 страниц**, максимум **15 страниц**. Решение Арсения. Не раздуваем под верхнюю границу feedback Кнатько (15-20 стр.) — плотный текст важнее объёма.

### Стек инструментов
- **Claude Opus 4.7 (1M context)** через Claude Code в VSCode — единственный основной инструмент.
- Если в ходе работы понадобится дополнительный — фиксируется в [AI_USAGE_LOG.md](AI_USAGE_LOG.md) разделе 1 с датой добавления.

### Журнал использования
Ведётся параллельно с написанием в [AI_USAGE_LOG.md](AI_USAGE_LOG.md) (формат: единая накопительная таблица — опция А). Каждый эпизод фиксируется в день эпизода, не задним числом.

### Структура папок (соответствует слайду 4 семинара Кнатько)
- `ai_pipeline/prompts/` — все значимые промпты
- `ai_pipeline/raw_outputs/` — сырые ответы Claude
- `ai_pipeline/verified/` — то, что прошло проверку и пошло в драфт

### Хранение и публикация (открытый вопрос)
GitHub vs Google Drive — Арсений принимает решение.
Рекомендация Claude: **GitHub** (версионирование = доказательство honesty, без protocol overhead для комиссии). Public или private — решение Арсения, обсуждается.
До решения — всё лежит локально в проекте.

### Семь критериев готовности дисклеймера (чек-лист со слайда 11)
1. Пайплайн виден (что до ИИ, что после)
2. Конкретика инструмента (модель + версия + поверхность)
3. Разграничение вклада (ИИ vs Арсений)
4. Честность про ошибки (галлюцинации, отклонённые правки)
5. Данные защищены (для Salmon — автоматически: внутренних данных нет)
6. Повторяемость (промпты сохранены и доступны)
7. Оценка эффективности (не «использовал», а «сократило время на X%»)
